<objective>
Close the one parity gap the contract work exposed, then record the decision, turn the
rule on and retire the debt, in the order CLAUDE.md requires.

**First, the CLI mate range (R-2).** During planning, `spur info --mate-teeth -5`
printed `"centre_distance": 12.25` and `--mate-teeth 3` printed `19.25`. The API refuses
both with a `422`. A centre distance to a gear that cannot exist is exactly the
plausible number L08 forbids, and the mismatch breaks REQ-cli-parity ("the same
errors"). The human decided on 2026-09-24 to fix it in this phase. Task 1 gives
`--mate-teeth` the API's range, as its own commit.

**Then the ratchet.** After Plan 04-02, the only thing still stopping
`disallow_any_explicit` is the pydantic mypy plugin, which by default writes an
explicit `Any` into the initialiser it generates for every model and reports it on the
model's `class` line. The human chose (R-1) to remove that with the plugin's two
settings, `init_typed` and `init_forbid_extra`. Together they make the generated
initialiser fully typed. That takes the six errors to zero with no suppressions and
changes nothing at runtime. Task 2 appends `L21` citing that decision; Task 3 turns the
rule on and retires the debt in the same commit.

Purpose: L14 promised a ratchet, not an exemption. The debt file asked for exactly this
— "turn `disallow_any_explicit` on and delete this file" — and this plan retires it that
way and writes down why, so no later agent turns it back off. Before that, it makes sure
no front end prints a number for a gear that cannot exist.

Output: `--mate-teeth` range-checked, with a parity test; `L21` (supersedes L14); the
house rule in `docs/CODING_VALUES.md`; the rule on in `pyproject.toml`, with the plugin
settings and an honest comment; the debt file resolved, moved and its INDEX row moved,
in the same commit as the rule turning on.
</objective>
