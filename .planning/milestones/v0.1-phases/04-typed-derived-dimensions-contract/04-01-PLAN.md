<objective>
Give the document every interface reads a real shape, and prove it end to end.

`derive()` returns `dict[str, Any]` today. A separate post-hoc function patches the mate
fields and a warning into that dict, so the mate keys appear only when a mate was asked
for. This plan replaces both with a single frozen pydantic model, `DerivedDimensions`,
built once, inside `derive()`, with every key always present and `null` where a value
does not apply (D-01, D-02, D-09). `/api/info` returns the model and `spur info` prints
it. Tests prove that the two front ends agree (D-13), that the OpenAPI document
describes the model (D-11), and that the UI still finds every key it reads (D-12). The
four gear-maths documents and the API endpoint table stop describing the dict (D-15).

Purpose: a renamed or dropped key is a surprise today for the UI, the CLI and any API
client, and the type checker cannot see it. After this plan, the checker sees the shape,
and three tests catch a broken contract without a browser.

Output: `DerivedDimensions` and the new `derive()` signature; `info()` and `cmd_info`
reading the model; three new tests (D-11 info half, D-12, D-13), a frozen-result test,
and the existing `test_calc.py` reads moved to attributes; five documents corrected; the
per-call cost of `derive()` measured and recorded.

This plan does **not** turn on `disallow_any_explicit`. The rule stays off in config
until Plan 04-03, so every commit here passes the current gate. The remaining `Any`
sites (health, schema, `_BlobCache`, `_f`, the pool, argparse, smoke, the test
parametrizations) belong to Plan 04-02.
</objective>

<flagged_assumptions>
1. **D-10's premise does not match the code, and the plan follows D-10 anyway.**
   CONTEXT.md says `root_fillet` and `recess_fillet` currently go out unrounded, and
   gives `0.4123456 → 0.412` as the one visible change. The code does not bear that out:
   `root_fillet()` (`calc.py:99`) and `recess_fillet()` (`calc.py:111`) already
   `round(..., 3)` internally. Rounding again with `r3()` does nothing, so **no value on
   the wire changes**. This was confirmed during planning by diffing `spur info` for a
   capped recess fillet (`--recess-width 12 --recess-fillet 3`) before and after a dry
   run: the values were identical. Task 1 still wraps both fillets in `r3()`, because
   D-10's rule — every length rounded once, at construction — is worth having in its own
   right. `L21` (Plan 04-03) records the corrected fact. The helpers' internal rounding
   is left alone, because `model.py` builds geometry from those values.

2. **`spur info --mate-teeth` has a gap that predates this phase. It is fixed later in
   the phase, and this plan keeps the current behaviour exactly until then.** Measured
   during planning: `spur info --mate-teeth -5` prints `"centre_distance": 12.25`, and
   `--mate-teeth 3` prints `19.25`. The API refuses both with a `422`. A centre distance
   to a gear with -5 teeth is the kind of plausible-looking number L08 forbids, and the
   mismatch is a gap in REQ-cli-parity. On 2026-09-24 the human decided to fix it in
   this phase (R-2): Plan 04-03 Task 1, as its own commit. Until then, Task 1 here keeps
   today's behaviour byte-for-byte, including `--mate-teeth 0` meaning "no mate". That

   range-checked.

**Step 1 — the model (D-01, D-03, D-09), in `calc.py`.**
Add a runtime `from pydantic import BaseModel, ConfigDict, Field`. Keep the
`TYPE_CHECKING` guard around the `GearParams` import exactly as it is; it exists
because of the `params → calc.check` import cycle, not to avoid pydantic. Remove `Any`
from the `typing` import.

Define `class DerivedDimensions(BaseModel)` immediately above `derive()`, with
`model_config = ConfigDict(frozen=True)` and a short class docstring. The docstring
says two things: this is the one document the API, the UI and the CLI all print; and
every key is always present, with `None` meaning a value does not apply or cannot be
computed honestly (L08).

Declare the 19 fields in this order, which is today's key order with the two mate
fields last. Use these types, each with a `Field(description=..., ...)`:
- `pitch_d: float`: "Pitch circle diameter."
- `tip_d: float`: "Tip (outside) diameter."
- `root_d: float`: "Root diameter."
- `base_d: float`: "Base circle diameter."
- `caliper_over_tips: float`: "Caliper reading across the tips; short of tip_d for an odd tooth count."
- `tip_thickness: float`: "Tooth thickness at the tip, as an arc."
- `root_thickness: float`: "Tooth thickness on the root circle, as an arc."
- `root_gap: float`: "Gap between teeth on the root circle, as an arc."
- `root_fillet: float`: "Root fillet radius actually used, after capping to the gap."
- `span_teeth: int`: "Number of teeth the span measurement is taken over."
- `span: float`: "Span (Wildhaber) measurement over span_teeth teeth, at zero backlash."
- `bore_effective: float | None`: "Bore diameter including print clearance; null with no bore."
- `recess_id: float | None`: "Face recess inner diameter; null with no recess."
- `recess_od: float | None`: "Face recess outer diameter; null with no recess."
- `recess_fillet: float | None`: "Recess floor fillet radius actually used; null with no recess."
- `web: float | None`: "Thickness left between the recesses; null with no recess."
- `warnings: list[str]`: "Sentences about values that were capped, dropped or cannot be computed."
- `mate_teeth: int | None`: "Teeth on the mating gear asked about; null when none was."
- `centre_distance: float | None`: "Working centre distance to the mate; null with no mate, or when the pair cannot mesh."

Every length field also gets `json_schema_extra={"unit": "mm"}`. `span_teeth`,
`mate_teeth` and `warnings` get no unit. **No field gets a default of any kind.**
Research verified that a default makes the key optional in OpenAPI, which contradicts
D-01's always-present contract (Pitfall 2). A default is also exactly how a missing
value could become a plausible number (L08). The one construction call below passes
every field explicitly.

**Step 2 — `derive()` absorbs the mate (D-02, D-10).**
The new signature is `derive(p: GearParams, mate_teeth: int | None = None, mate_shift: float = 0.0) -> DerivedDimensions`.
Keep the docstring's first line. Add a sentence saying that with `mate_teeth` it also
reports the working centre distance to that gear, or a warning and `None` when the pair
cannot mesh. Explain why here: the API and the CLI share this, so the decision that an
impossible pair is a warning on an otherwise fine gear — not an error, and not a number
