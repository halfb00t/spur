<objective>
Move one real CAD build out of the serving process and prove it left.

This is the tracer slice for Phase 2: a single `GET /api/model.stl` request travels
admission control -> parent byte cache -> affinity routing -> a spawned worker process ->
`model.export` -> bytes -> HTTP response, with `spur.app` structurally unable to reach the
CAD kernel. Everything later in this phase (timeouts, failure mapping, health fields,
measurement) expands outward from this proven path.

Purpose: REQ-cad-off-event-loop's root cause is that the kernel runs in the process that
serves `/api/health`. Proving the boundary end-to-end on the first commit is what makes an
architectural dead-end cheap — in particular the one this plan has to solve on contact:
the parent needs a reference to a worker-side function in order to submit it, but D-02's
`allow_indirect_imports = false` contract forbids any static import path from `spur.app`
to `cadquery`. Task 1 resolves that (dynamic import in the worker entry point) and Task 3
proves the resolution against the real linter.

Output: `src/spur/build_errors.py`, `src/spur/pool.py`, a rewritten model endpoint, the
byte cache relocated to the parent, the new import-linter contract, and the one real
end-to-end worker test.
</objective>

1. **The dynamic-import escape is assumed to satisfy import-linter, not verified.**
   `grimp` builds its graph from `import` / `from ... import` statements in the AST; a
   call to `importlib.import_module("spur.model")` is expected to be invisible to it. If
   `make lint-imports` reports a broken contract in Task 3, stop and surface it — the
   alternatives (a string-dispatch entry point, or renegotiating D-02's
   `allow_indirect_imports = false`) are a decision, not a workaround.
2. **`asyncio.TimeoutError` is not `TimeoutError` on Python 3.10.** They were only unified
   in 3.11, and CI runs 3.10 and 3.12 (L14). This plan therefore defines `BuildTimeout` in
   `build_errors.py` now, so Plan 02-03 never has to catch a version-dependent builtin. If
   this turns out to be wrong on the installed 3.10, say so rather than deleting the class.
3. **`pytest`'s `filterwarnings = ["error", ...]` turns a `ResourceWarning` from a leaked
   subprocess into a test failure.** Expected to be a feature, not an obstacle: it is what
   will catch a pool that is not shut down. If it produces an unavoidable failure from
   inside `concurrent.futures` itself, surface it before adding an ignore.
