<flagged_assumptions>
1. **Branch precedence (CONTEXT.md discretion on wording; D-06 fixes the three branches).**
   After the poll finds no run, `no_run_report` reads the squash commit once. A token in
   that message is reported first -- it is the one cause the tool can establish, and a
   token means GitHub will never start a run whatever the polls saw. Otherwise, a failed
   final poll read or a failed commit read gives the last-error report; otherwise the
   nothing-appeared report with the Actions URL. `last_error` holds the most recent failed
   read and is cleared by a successful one, so "reads succeeded and nothing appeared" is
   what the final poll actually saw.

   36122394253; the probe passes `last_error=None` to check the read, the URL derivation
   and the token search against GitHub's real responses. It merges nothing and writes
   nothing.

   -> `https://github.com/<owner>/<repo>/actions/workflows/ci.yml`), the shape `gh api`

   non-zero; the link would be wrong, not the verdict.
