<objective>
Close the one production-latent `must` item in the kernel doorway (D-08, D-09): the
process-global `_build_cached` hands every caller the same mutable `cq.Solid`, and
`exportStl()` attaches a triangulation to whatever solid it is called on. Two consequences
were measured, one filed and one found at planning:

- A later `.BoundingBox()` on the cached object reads the mesh, not the exact BREP: zlen
  7.500000200000001 before any export, 7.587720608891235 after a preview STL export,
  7.519603716332508 after a fine one (`GearParams()`, teeth=19; the debt file, reproduced
  exactly at planning).
- **Export content depends on export history** (planning probe, 2026-09-25, pre-fix code):
  after a fine STL export of `GearParams()`, a preview STL export of the same gear returns
  the fine mesh -- 46,278 triangles, not the 9,066 a first preview export gives -- because
  OCCT keeps an existing triangulation that already satisfies the coarser tolerance. The
  debt file's "STL bytes unaffected" held only for the preview-then-fine order.

**The fix is fixed by the human's plan-time decision (D-08 amendment (b)): `_write_export`
meshes `shape.copy()`.** `BRepTools.Clean_s` (the correct name of the debt file's `.Clean`)
was rejected although it measured 4-13 % faster, because it strips the mesh *after* export:
the cached object would carry a mesh for the whole export window, while `build()` releases
`_LOCK` before callers read the solid -- the invariant would hold only between exports.

**The proof is content equivalence, not a byte diff (D-08 amendment (c)).** OCCT export is
not byte-reproducible across independently built solids (8/20 in research's rerun); triangle
count and decoded volume are (planning probe: 8 preview and 4 fine independent builds of
`GearParams()` gave 9,066 / 46,278 triangles every time, decoded-volume difference 0.0).

**Task 1, the tracer**: RED tests for both consequences, the one-line fix, the autouse
reset deleted (D-09), and the public doorways re-probed end to end -- before anything else.
**Task 2**: L24 with every number, and the debt file retired in the commit that completes
the fix.

Purpose: a number read from a cached solid is the solid's number (L08), and an export is
the same bytes-worth of content whatever this worker exported before.
Output: `model.py` one call changed, two new tests and one helper refactor in
`test_model.py`, the autouse reset gone from `conftest.py`, L24, the resolved debt file.
</objective>
