<objective>
Close the one blocking gap 05-VERIFICATION.md found (ROADMAP SC-1, 05-REVIEW.md CR-01).
`make pr.land`'s squash-message check, `message_refusals()`, reused the commit-msg hook's
cut at git's `commit -v` cut line on text git never touches -- a PR title and body. A
body carrying a line identical to that cut line, then a skip token, passed with zero
refusals, and `land()` would have squash-merged the whole, untruncated body as `main`'s
commit message: a run-less commit on `main`, through the tool built to stop exactly that.
Re-run during planning on this checkout: the verifier's one-liner still prints `[] []`.

**Decision (a) -- the route for the verifier's first bullet: the cut becomes the hook's
own step, not the search's.** `find_skip_tokens(message)` searches exactly the text it
is given. The hook's entry, `main()`, applies `message_to_check()` to the editor buffer
git hands it before calling `find_skip_tokens`. `message_refusals()` keeps its one line,
`find_skip_tokens(subject + "\n\n" + body)`, which now searches the whole PR text. This
is the verifier's first route -- the PR-text check calls the raw search and never goes
through `message_to_check` -- taken by moving the cut out of `find_skip_tokens` rather
than routing around it. Against D-02's "one pattern, so the two checks cannot drift
apart": there is still one `SKIP_TOKEN` and one `find_skip_tokens`, both checks call it,
and only the input differs -- the one caller that knows its text came from git's editor
removes what git discards. Against the module's own "over-matching is the safe
direction": the full search is now the default, so the next caller gets the safe
behaviour without asking for it. Rejected: a `cut: bool` parameter (with a default it
either re-creates this bug for the next caller that omits it or is a no-op for pr.land;
without one, about twenty test call sites change for no behaviour); a second
`find_skip_tokens_raw()` (the unsafe variant keeps the natural name); an inline
`SKIP_TOKEN.finditer` in `pr_land.py` (leaves `find_skip_tokens` cutting by default and
duplicates the match extraction in a second module -- the drift D-02 exists to prevent).
`pr_land.py`'s code does not change; its `message_refusals` docstring says why no cut
applies to PR text.

**Decision (b) -- the verifier's third bullet, the hook side: fixed in this plan (Task
2), and the part no hook can see is filed as `must` debt in the same commit.** A planning
probe (flagged assumption 1) showed the hole sits on the path every commit here takes:
`git commit -m` and `-F` record a hand-written cut line and the token below it, while the
hook stops reading at that line. Git truncates at the cut line only with
`-v`/`commit.verbose` or `--cleanup=scissors`, and it appends `-v`'s diff only to an
editor buffer; githooks(5): "All the git commit hooks are invoked with the environment
variable GIT_EDITOR=: if the command will not bring up an editor". So the hook cuts only
when git ran an editor. That keeps the one case the cut exists for -- `git commit -v`'s
staged diff, where this repository's own tests and docs name tokens -- and
`test_token_only_below_the_scissors_line_gives_no_tokens` stays true for the hook path,
pinned to an editor session; and it closes `-m`/`-F`. Not taken: dropping the cut
(refuses every `git commit -v` whose diff names a token, and breaks that test's intent);
the verifier's `git config --get commit.cleanup` check (config cannot see a `-v` typed on
the command line, and `commit.verbose` truncates too, so for everyone here it amounts to
dropping the cut). What remains -- an editor session without `-v` in which the author
types git's cut line by hand above a token -- cannot be told apart by content, is
backstopped, and is filed: `docs/tech_debt/active/2026-09-25-commit-msg-hook-trusts-a-hand-typed-cut-line.md`,
`Severity: must`, with both ways to close it and their costs.

**Reversibility.** Both decisions are `reversible`: `find_skip_tokens` and the hook's
entry have only in-repository callers, no data, published contract or external system
reads them, and each change reverts in a few lines. Nothing here is `one-way`, so there
is no `checkpoint:decision` and the plan is `autonomous: true`.

**No decision-log entry.** L22 says the hook refuses the tokens "above git's `commit -v`
scissors line" and that `message_refusals` reuses `find_skip_tokens` "unmodified". Both
stay true after this plan. The log is append-only and nothing here supersedes L22; the
plan makes its implementation do what it says.

**Task 1, the tracer.** The verifier's reproduction becomes a failing `message_refusals`
test and a failing whole-path `land()` test, the cut moves into the hook's `main()`, and
the reproduction one-liner is re-run and exits 0 -- end to end, before anything else.

**Task 2.** The hook cuts only when git ran an editor, proven by a real refused
`git commit -m`; the residual is filed as debt with its INDEX row.

Purpose: SC-1 true again on both paths onto `main` -- a skip token cannot reach `main`'s
squash commit through `make pr.land`, and the commit-msg hook no longer skips text git
will record.

Output: the two scripts and their tests changed, one debt file and its INDEX row.
