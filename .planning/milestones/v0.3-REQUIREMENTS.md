# Requirements: spur — milestone v0.3 Clean Ledger

**Defined:** 2026-10-01
**Core Value:** A number this tool prints is a number someone will cut metal to — every
dimension is computed honestly or reported as a warning, never guessed (L08).

Scope fixed in `PROJECT.md` ("Current Milestone: v0.3 Clean Ledger"). No research pass:
every item is internal to the codebase and its debt file already states the next step
(`docs/tech_debt/active/`). The choices the human took at kickoff (2026-10-01) are baked
into the wording: debt-only, the root lead-in is **warned, not re-cut**; the latency bar is
**explained, then demonstrated or superseded by a logged decision**; the `make verify` bar is
**set from the profile at discuss-phase**, not before.

REQ-IDs continue the project's `REQ-slug` convention (`milestones/v0.2-REQUIREMENTS.md`).

## Rules every requirement lives by

- **Same part.** No new `GearParams` field. `tests/regression/pre_v0_2.json` (44 records, 85
  cases, `warnings` included) stays byte-unchanged and green through every phase — the
  standing L05/L26 proof. A requirement that would change a record stops and asks; a
  regeneration is its own commit under its own `Lxx` (fixture provenance D-03).
- **Retired in the fixing commit.** A debt file flips `Status: resolved`, gains the sha, is
  `git mv`'d into `docs/tech_debt/resolved/` and its INDEX row moves — in the same commit as
  the fix (CLAUDE.md). Never filed-and-moved-on.
- **Measured, never tuned.** A bar is demonstrated on the harness as it stands, or the
  harness/bar is changed by a logged `Lxx` stating why and re-measured. No parameter is
  adjusted until a pass appears (the latency debt file's own prohibition; L08).
- **Phases land as PRs** on `gsd/phase-NN-*` through `make pr.land PR=N` (L22/L25);
  `.planning/` rides the same PR. The hook's `make verify` runs on every commit.

## v0.3 Requirements

### Latency bar

- [x] **REQ-latency-observations-explained**: The two observations the waiver left
  unexplained each get a cause ruled in or out, by the bounded investigation the debt file
  prescribes — the pair re-run with a server restart between runs, and with the poller in
  its own process — written up in the shape of
  `milestones/v0.1-phases/02-*/02-LATENCY-INVESTIGATION.md`. The observations: (1) the
  second run of a pair, inheriting the first's `_EXPORTS`, reads worse every time
  (2.02→2.45, 2.32→2.35, 1.31→2.10, 1.86→2.02); (2) idle p95 is 0.6 ms in six of eight
  runs, so a pass and a miss are ~0.1 ms apart — the harness's resolution floor.
  *Acceptance*: for each observation the write-up names the candidate that survived and the
  measurement that ruled the others out (four instant ~2.6 MB sends at t=0; worker-side
  state after the first batch; a shorter load window read at the floor). No `src/` or
  `bench/` change under this requirement — it is a measurement, not a fix.
- [x] **REQ-latency-bar-demonstrated-or-superseded**: After the above, one of two outcomes,
  never a third: (a) `bench.latency`'s `scenario_concurrent` reads ≤2.00× idle p95 on
  **both** runs of one session on the harness as it stands; or (b) the harness or the bar
  is changed — restart between runs, a higher `MIN_SAMPLES`, or an absolute threshold the
  harness can actually resolve — as a logged `Lxx` stating the measured reason, and the
  bar is re-measured on the changed harness on both runs of one session. *Acceptance*:
  `bench/RESULTS.md` records the runs with host and load; L18's text and the container
  `HEALTHCHECK` (if it cites the bar) say what was measured, not what was accepted;
  `2026-09-23-concurrent-latency-bar-waived.md` retires with the sha. The composed worst
  row (Phase 12, 29.42 s) under ten concurrent builds — the question re-homed into this
  file by 12-CONTEXT.md D-04 — is measured once and recorded, whatever it reads.
