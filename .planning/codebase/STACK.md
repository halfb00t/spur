# Technology Stack

**Analysis Date:** 2026-10-02

## Languages

**Primary:**
- Python 3.12 - All production code (`src/spur/`), CLI, API, CAD kernel bindings, test suite
  - Limited to 3.12 only because `cadquery-ocp` wheels only publish for 3.12 (L23, documented in `Makefile:10-14`)

**Secondary:**
- JavaScript (ES2022) - Vendored browser runtime only (web UI and 3D viewer)
  - Not part of the build pipeline (no Node in Docker) — the bundled output is committed
- Bash - Deployment scripts (`docker/refresh-requirements.sh`, GitHub Actions workflows)

## Runtime

**Environment:**
- Python 3.12.x (bare minimum to parse/execute)
- CPython interpreter - enforced by `make venv` which searches for `python3.12` only (`Makefile:13-14`)

**Package Manager:**
- pip with pinned closure
  - `pyproject.toml` (`src/spur/` packages with loose version ranges for dev environments)
  - `requirements.txt` (exact frozen closure for Docker images, generated by `docker/refresh-requirements.sh`)
  - Lockfile: `requirements.txt` is the committed lockfile for production; `web/package-lock.json` for the web bundle

## Frameworks

**Core:**
- FastAPI 0.141.1 (`requirements.txt:17`) - HTTP API and ASGI app serving the web UI and endpoints
  - Router and middleware only; CAD builds run in separate worker processes (D-01, D-02)
- CadQuery 2.8.0 (`requirements.txt:13`) - Parametric CAD kernel for spur gear solid generation
  - Wraps OpenCascade via `cadquery-ocp` 7.9.3.1.1 (`requirements.txt:12`)
  - Runs only in worker processes, never in serving process (import-linter contract, `pyproject.toml:179-188`)

**Validation & Data:**
- Pydantic v2.13.5 (`requirements.txt:26`) - Parameter model validation and JSON schema generation
  - `GearParams` model enforces rules at boundary; all math trusts validated input (L08, `pyproject.toml:104-107`)
  - mypy plugin enabled (`pyproject.toml:96-99`) for strict generated `__init__` type checking

**Server Runtime:**
- Uvicorn 0.53.0 (`requirements.txt:35`) - ASGI server running FastAPI
  - Configurable via `SPUR_WORKERS` (default 1, single serving process)
  - Each worker spawned as separate process by uvicorn

**Testing:**
- pytest 8+ (`pyproject.toml:21`) - Test runner, configured in `pyproject.toml:115-123`
  - Fixtures and mocking via pytest built-ins
  - Coverage measurement in place (`pyproject.toml:125-130`)
  - No coverage floor enforced yet (deferred, documented in `docs/tech_debt/active/2026-09-21-no-coverage-floor.md`)

**Build/Dev:**
- Hatchling 1.25+ (`pyproject.toml:2`) - PEP 517 build backend
  - Builds wheel package to `src/spur/` namespace package
- Ruff 0.14+ (`pyproject.toml:23`) - Linter with correctness rules only (no formatting, L16)
  - Config: `pyproject.toml:37-78` (high-signal set, not "ALL")
  - No ruff format intentionally — hand-aligned geometry comments are preserved
- mypy 1.18+ (`pyproject.toml:24`) - Strict static type checker
  - Configured at `python_version = "3.12"` to match runtime
  - `--strict` enforced across all modules (src, tests, docker, bench, scripts)
  - No `Any` allowed explicitly (`pyproject.toml:89`)
- import-linter 2.3+ (`pyproject.toml:25`) - Enforces module boundary contracts
  - Four contracts defined in `pyproject.toml:131-189` (app vs tests, calc vs CAD kernel, CLI vs web policy, maths vs logging)
  - Prevents accidental kernel imports in serving process (D-02)
  - Prevents CAD kernel from being loaded on keystroke (calc.py pure math policy, D-XX)
- pre-commit 4+ (`pyproject.toml:26`) - Git commit gate
  - Runs `make verify` on pre-commit hook stage and `skip_tokens` check on commit-msg stage
  - Config: `.pre-commit-config.yaml:1-47`

## Configuration

**Environment Variables (used in production):**
All documented in `README.md:67-95` and enforced via `int_env()` at `src/spur/__init__.py:8-13`:

| Variable | Default | Purpose |
|----------|---------|---------|
| `SPUR_HOST` | `0.0.0.0` | Bind address (set to `127.0.0.1` in `compose.yaml:8` for localhost only) |
| `SPUR_PORT` | `8000` | Listen port |
| `SPUR_WORKERS` | `1` | Uvicorn serving processes (HTTP routing and caching only, no CAD builds) |
| `SPUR_BUILD_WORKERS` | `2` | Separate CAD builder processes (ProcessPoolExecutor pool size) |
| `SPUR_BUILD_TIMEOUT` | `30` (seconds) | Per-build ceiling before worker is killed |
| `SPUR_ROOT_PATH` | unset | URL prefix when served under reverse proxy sub-path |
| `SPUR_SOLID_CACHE` | `4` | Solids kept resident per worker (memory sweep tuning) |
| `SPUR_EXPORT_CACHE_MB` | `64` | Total exported bytes cached in serving process (LRU by byte budget) |
| `SPUR_MAX_QUEUED_BUILDS` | `2 × SPUR_BUILD_WORKERS` | Requests queued before API returns 503 |
| `SPUR_LOG_LEVEL` | `INFO` | Root logger level (JSON stderr logging, `records.py:85-130`) |

Set at container runtime in `compose.yaml:9-16` and `Dockerfile:36-38`.

**Build Configuration:**
- Python: `requires-python = ">=3.12,<3.13"` (`pyproject.toml:10`)
- Target bytecode: Python 3.12 only
- Ruff lint rules: custom high-signal set (no ALL, no DOC, no ANN) — see `pyproject.toml:50-66`
- mypy strict mode with Pydantic plugin: `pyproject.toml:80-99`
- Test markers and warnings: `pyproject.toml:115-123`

**Docker Build Configuration:**
- Base image: `python:3.12-slim-bookworm` (`Dockerfile:3`)
- Shared libraries: `libgl1 libx11-6 libexpat1` (`Dockerfile:7`) — required by OCP and VTK wheels
- Install method: `pip install --no-deps` with pinned `requirements.txt` (avoids ~550 MB of transitive unused packages)
- Smoke test: `docker/smoke.py` validates CAD kernel and ASGI app in image
- Entry point: `spur serve` (CLI command, `Dockerfile:56`)
- Health check: Python HTTPClient against `/api/health` (p95 < 2.3 ms, measured in `bench/RESULTS.md`, `Dockerfile:53-54`)
- Artifacts committed: vendored three.js bundle in `src/spur/static/vendor/` (568 KB minified+gzipped, reproducible from `web/package.json`)

## Platform Requirements

**Development:**
- macOS, Linux, or WSL with Python 3.12 installed or `brew install python@3.12`
- Docker and Docker Compose (for `make check` and `make up`)
- Node.js 22.x only needed when updating three.js (`web/` build runs locally, output committed)

**Production:**
- Docker (multi-arch: linux/amd64 and linux/arm64 via buildkit)
- Memory: 4g default in `compose.yaml:26` (measured peak 2.8 GB under 40-gear sweep with 2 workers, L17)
- CPU: Minimal requirements — the app is I/O-bound during serving, compute-bound only in worker subprocesses
