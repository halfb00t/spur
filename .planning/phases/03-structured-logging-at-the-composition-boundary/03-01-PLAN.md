<objective>
One request leaves one JSON line, end to end — then the whole per-request vocabulary.

This plan creates `src/spur/records.py`, the kernel-free module that owns every logging
decision this phase takes (D-17), wires it at both composition points, and makes a real
`/api/model.stl` request emit a structured `export.served` record proven by reading the
formatted line back through `json.loads`. It then completes `app.model()`'s per-request
vocabulary — the correlation id (D-13), the gear identity (D-10), the three `source`
values (D-11), `duration_ms` (D-12) and `build.started` — and pins the record format's
edges: the level threshold, the empty-parameter case, one-physical-line encoding, stable
key order, and integer-millisecond precision.

Purpose: `docs/tech_debt/active/2026-09-21-no-structured-logging.md` says the only
evidence a production request leaves today is its HTTP status, and names the second-order
risk — that the first person who needs visibility reaches for a direct stream write and
the logging decision gets made by accident at the worst possible moment. This plan is the
decision, taken deliberately, with the field names picked once (the debt file's own
instruction) and asserted as literal strings by tests so a rename can only be a deliberate
change.

Output: `src/spur/records.py`, a configured stderr JSON logger at `cli.cmd_serve` and
`app.lifespan()`, `export.served` and `build.started` emitted from `app.model()`'s
existing branches, `tests/conftest.py`, `tests/test_records.py`, and new `caplog` branch
tests in `tests/test_api.py`.
</objective>

<flagged_assumptions>
1. **RESEARCH.md falsified D-05's stated assumption, and this plan implements the
   consequence as a requirement, not a fallback.** CONTEXT.md D-05 assumed that with
   `SPUR_WORKERS>1` uvicorn's child processes inherit the parent's root-logger
   configuration, and named an idempotent second `configure()` in `app.py`'s `lifespan()`
   as the rejected-for-now alternative. RESEARCH.md disproved the assumption two ways —
   by reading the installed `uvicorn` 0.53.0 `_subprocess.py` /
   `supervisors/multiprocess.py` (children are `multiprocessing.spawn` processes, and the
   child's target callable is `subprocess_started`, never `cli.cmd_serve`), and by a live
   reproduction showing a spawned child's root logger holds zero handlers immediately
   after the parent installed one. The `lifespan()` call site is therefore **mandatory**:
   without it, every per-request record this phase adds vanishes silently the moment a
   deployer raises `SPUR_WORKERS`. Both call sites ship; `configure()` is idempotent so
   the default `SPUR_WORKERS=1` path, where both run in one process, does not double-print.

2. **The `logger` envelope key reads `spur.records`, not the calling module.**
   CONTEXT.md's `<specifics>` target shape illustrates `"logger": "spur.app"`, but
   envelope keys are explicitly Claude's Discretion, and D-17 makes the five helpers in
   `records.py` the only call sites by construction. A per-caller logger name would be a
   second, weaker copy of `event`, which already names the branch precisely. The key still
   does its D-02 job: it separates `spur.*` records from `uvicorn.access` /
   `uvicorn.error` in the one stream. Stated here so this reads as a decision rather than
   as drift.

3. **The local in `app.model()` cannot be called `request`.** `model()` already takes a
   FastAPI `request: Request` parameter, which `wants_gzip` reads. The correlation id
   local is `request_id`; the emitted **field** name stays `request` per D-13. Shadowing
   the FastAPI parameter would silently break content-encoding negotiation.
</flagged_assumptions>

**`src/spur/records.py` — the module (D-01, D-17).** Module docstring in the shape of
`build_errors.py`'s: say *why* this is its own module — it is imported by `spur.cli` and
`spur.app` and must reach neither `cadquery`/`OCP` nor `fastapi`/`starlette`/`spur.app`,
which the four existing import-linter contracts already forbid, so no new contract is
needed. Say why it is not named after the stdlib module it wraps. Imports: `json`,
`logging`, `os`, `sys`, `datetime`, plus `from . import __version__` and
`from .params import GearParams` — nothing else.

Contents, in this order:

- `_LOG = logging.getLogger(__name__)`. Never the bare module-level `logging.info`-style
  calls — ruff `LOG015` forbids them, and flagged assumption 2 above records why the
  emitted `logger` value is this module rather than the caller's.
- `_STANDARD_LOGRECORD_ATTRS`: a module-level `frozenset` of the standard `LogRecord`
  attribute names, transcribed from RESEARCH.md §"Code Examples"' live reproduction
  against the installed interpreter (`args`, `created`, `exc_info`, `exc_text`,
  `filename`, `funcName`, `levelname`, `levelno`, `lineno`, `module`, `msecs`, `msg`,
  `name`, `pathname`, `process`, `processName`, `relativeCreated`, `stack_info`,
  `taskName`, `thread`, `threadName`, and `message`/`asctime` which `Formatter` may add).
  One constant, referenced by the formatter and by its test — never re-derived by eye in
  two places. Carry a comment naming the interpreter version it was verified against.
- `_JsonFormatter(logging.Formatter)`: `format(record)` builds a payload dict in a fixed
  order — `ts`, `level`, `logger`, `event`, `version` — then appends every attribute of
  `record.__dict__` that is not in `_STANDARD_LOGRECORD_ATTRS` and is not `event` (which
  the envelope already took), in the order the record carries them. `ts` is ISO-8601 UTC
  derived from `record.created`. `level` is `record.levelname`; `logger` is `record.name`;
  `version` is `__version__`. Serialize with `json.dumps(payload, default=str)` and the
  default `ensure_ascii`: `default=str` so an unexpected non-serializable value can never
  raise inside a log call and turn a 422 into a 500, and ASCII escaping so one record is
  one physical line regardless of the stream encoding `docker logs` or a pipe hands us.
  No `sort_keys` — insertion order is the stable order (see the ordering criterion below).
  Traceback text does not ride on records: `BuildError`'s own message already carries the
  kernel text, and `BuildTimeout`/`BrokenProcessPool` have no kernel traceback at all
  (D-06's accepted cost, RESEARCH.md Open Question 1).
- `_JsonHandler(logging.StreamHandler)`: a subclass with no added behaviour, used purely
  as the identity marker `configure()` checks. Comment must say that: the idempotency
  state lives on the object it describes rather than in a module-level flag, so a test can
  tear the handler down without reaching into module privates, and a re-imported module in
  a spawned worker cannot resurrect a stale flag.
- `_parse_level(raw)`: `logging.getLevelName(raw.upper())` and return it when it is an
  `int`, else `logging.INFO`. Comment must record why this and not a hand-written mapping
  (`logging.getLevelNamesMapping` is 3.11+, and the project floor is 3.10;
  `logging._nameToLevel` is private), citing RESEARCH.md Pattern 3's verification that
  `getLevelName` returns `20` for a valid name and a `Level …` string for nonsense.
- `configure()`: takes no arguments. Return immediately if any handler already on the root
  logger is a `_JsonHandler`. Otherwise construct one `_JsonHandler()` (stderr is
  `StreamHandler`'s default, which is the point — D-04), give it a `_JsonFormatter`, add
  it to the root logger, and set the root level from `_parse_level(os.environ.get(
  "SPUR_LOG_LEVEL", "INFO"))`. It reads the environment itself rather than taking a level
  argument, so the two call sites cannot disagree about the level within one process —
  which is exactly the failure the idempotency guard exists to prevent. Comment the stderr
  choice with the convention it matches (`cli.py` puts product output on stdout and
  diagnostics on stderr; uvicorn's default access-to-stdout split collapses into this one
  stream; `docker logs` captures both, so nothing is lost).
- `_gear_fields(p)`: returns `{"slug": p.slug(), "params": p.model_dump(
  exclude_defaults=True)}` — D-10's identity, built in exactly one place. `params` is the
  shareable-link form L05 keeps stable, so a failed build is reproducible by pasting it
  back into a query string. An all-default gear yields an empty object, which is emitted
  as such, not omitted.
- `_ms(seconds)`: returns `round(seconds * 1000)` as an `int`. Comment must state the
  contract, including the tie-break: Python's `round` is half-to-even, and the value is
  never a float — sub-millisecond precision is false precision given monotonic-clock
  granularity and the IPC this duration deliberately includes (D-12).
- `_emit(level, event, fields)`: calls `_LOG.log(level, event, extra={"event": event,
  **fields})`. The event name is passed as the message *and* as a field: as a field
  because it is the record's primary key for any reader, and as the message so the
  degraded paths D-05 names (a bare `uvicorn spur.app:app`, `docker/smoke.py`) still print
  something meaningful through stdlib's `lastResort` handler instead of an empty line.
  Never an f-string in a log call — ruff `G004` — which is enforced by construction
  because `app.py` and `pool.py` never call `logging` directly (D-17).
- `export_served(request, p, fmt, quality, *, source, encoding, duration_s)`: emits
  `export.served` at INFO (D-15) with `request`, the `_gear_fields` identity, `fmt`,
  `quality`, `encoding`, `source` and `duration_ms` (D-11, D-12, D-13). Comment that
  `source` has exactly three reachable values and name the code path each one is.
