Planner choices recorded here:
- Codec location: `din5480.py`, since the designation is the standard's notation (31-RESEARCH layout). `Designation` is a
  NamedTuple whose field names equal ShaftParams' four, so Phase 33 builds `ShaftParams(**d._asdict())` and gets the
  boundary's own refusals.
- `DesignationError(ValueError)` carries `token: str`, so Phase 33 names the token in its 422 without parsing a message.
- Length bound 64 code points (31-RESEARCH Pattern 4): `W 835.000000x10.000000x82x11a` is 29 characters, so 64 refuses
  nothing real and bounds every regex input.
- Grammar, in order: the length bound; empty input; the type letter `W` (an `N` gets its own sentence: a hub is not
  supported; any other first word is named as the bad token); one optional ASCII space; `re.split(r"[xX]", rest,
  maxsplit=3)` must give four tokens (maxsplit keeps any x inside the fit token in the last token); reference_d and module
  each `re.fullmatch(r"[0-9]+(?:[.,][0-9]+)?")`; teeth `re.fullmatch(r"[0-9]+")`; fit `re.fullmatch(FIT_PATTERN)`; only
  then `float(token.replace(",", "."))` and `int(token)`. `[0-9]` never `\d` (Unicode digits), fullmatch never search,
  no `float()` on unchecked text (31-RESEARCH Pitfall 6).
- Printing: `repr(float(v)).removesuffix(".0")`, the shortest string that round-trips a float; `:g` keeps six
  significant digits and loses `25.123456`.
- D-14 debt route: option 2, re-target (31-RESEARCH Open Question 6): splitting would need a resolved file carrying its
  own commit's sha, which a commit cannot hold (the Phase 13 follow-up-commit precedent). The pyproject.toml C4 comment
  carries the same stale phase number and is corrected in the same commit (same concern: the widening is Phase 32's).
</objective>
