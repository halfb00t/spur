Planner choices recorded here (Claude's Discretion and Open Questions resolved at plan time):
- Expression order (31-RESEARCH Pitfall 2: "pick one and pin it"): `x = (d_B - z*m)/(2*m) - SHIFT_TERM`, and
  `xm = x * m`. Measured at plan time over four orders, it is the only one under which all three D-19 cases fall outside
  the bare range: (17.6, 0.8, 20) -> 0.45000000000000084, (30, 2, 14) and (25, 1.25, 19) -> -0.050000000000000044. The
  `xm/m` order reads (25, 1.25, 19) as exactly -0.05, which a bare comparison accepts, so D-19's "each seen red" would
  fail for it. D-19 quotes 0.4500000000000008 for the upper case, the `xm/m` order's value one ulp lower; under the
  chosen order the default reads 0.44999999999999996, the "another expression order" value D-19 anticipates. The SUMMARY
  records this corrected D-04/D-19 wording. `0.45 + 0.2/2 == 0.55` is exact in binary64 (checked), so the derived
  SHIFT_TERM equals the literal.
- Field bounds (31-RESEARCH A3, provisional; Phase 32's sweep sets the solid fields' bounds, ROADMAP Phase 32 criterion
  3): reference_d 3 to 850, module 0.5 to 10, teeth 6 to 82, splined_length 1 to 500, end_chamfer 0 to 10 (0 = none),
  shank_d 1 to 850, shank_length 0 to 500 (0 = none). Widening later is additive; no link exists before Phase 33.
- Solid-only names and defaults (Discretion): splined_length 30, end_chamfer 1.0 (below the 1.25 mm tooth height at
  h_fP 0.55), shank_d 25 (= reference_d, a shoulder above the 24.75 mm tip), shank_length 20, recorded for the human's
  review in the SUMMARY. Cross-field rules among them (chamfer against tooth height, shank against tip) are Phase 32's,
  with the solid (31-RESEARCH Open Question 5): this plan enforces ranges only.
- Groups (schema metadata, not frozen): `Spline` for reference_d, module, teeth, fit, splined_length, end_chamfer;
  `Shank` for shank_d, shank_length.
- The range refusal lives in `shaft_calc.check_shaft`, reached from `ShaftParams._feasible` by a local import, the
  `params.py` pattern, so Phase 33 serves it as the same `infeasible` 422.
