<objective>
Fill the contract-named, empty `src/spur/din5480_tables.py` with the one loader every consumer uses: a strict pydantic schema
with provenance on every row (D-03), the structural invariants that make a transcription checked rather than trusted
(D-04, REQ-tables-transcribed-twice), a process-wide accessor read from `SPUR_DIN5480_TABLES` once (D-02, D-13), and the
size and fit lookups the maths needs, all built and tested against a synthetic fixture (research's primary
recommendation: build against invented filler plus approved anchors, wire the real file last).

Planner choices (Claude's Discretion, CONTEXT: the schema's shape, where the loader lives):
- The schema is research Pattern 6 with three refinements: `Provenance.pages` is a tuple (a size row spans the nominal
  and the inspection page); `ColumnRow` carries the module group's own bounds (`module_min_mm`, `module_max_mm`) instead
  of a group number, so the group edges come from the file too; the header words are the field names (`d_b_over_mm` for
  "über", `d_b_upto_mm` for "bis") so the A1 convention lives in one lookup, `Tables.column_for`, and 34-16 can reverse
  it without touching a read.
- Provenance is not free text: `part_2_provenance(module)` derives clause, table pair and pages from the module's index
  in `PART_2_MODULES` (section 4 + i, tables 2 + 2i and 3 + 2i, pages 8 + 2i and 9 + 2i; research Table structure), and
  `TABLE_7_PROVENANCE` is Part 1, clause `10.9`, table `7`, page 24. A row whose provenance differs is refused, which
  is what keeps "9" and "section 9" from becoming a spurious disagreement between two reads (research A11).
- The loader is module state in `din5480_tables.py` (research Pattern 1): an accessor, not an argument threaded through
  `derive_shaft`, `build_shaft`, `model.export` and the pool. It is the project's third piece of documented process
  state beside the kernel lock and the build semaphore (CODING_VALUES "State"), and 34-17 logs it in L50.
- A failed load is cached too, so a broken file in a library caller costs one read, not one per keystroke.

Purpose: one checked object for the whole process, so no table number can print from a file nobody validated.
Output: the module, a synthetic fixture, ~45 light tests, the conftest isolation.
</objective>
