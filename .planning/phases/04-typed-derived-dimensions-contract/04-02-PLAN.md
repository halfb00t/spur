<flagged_assumptions>
1. **Two of the discretion spellings in RESEARCH.md and PATTERNS.md do not type-check,
   and this plan uses the ones that do.** Both were verified during planning by applying
   every fix to a scratch copy of the tree and running mypy and the full suite
   (99 passed):
   - `cli._add_gear_args` with `kw: dict[str, object]` produces **8** `arg-type` errors,
     because `argparse.add_argument`'s stub types each keyword separately. Explicit
     keyword calls do type-check, with `field.annotation` narrowed by an `is not None`
     test.
   - `docker/smoke.py` with `MutableMapping[str, object]` needs **two** casts, not one:
     `status = message["status"]` breaks as well as `body.extend(...)`. starlette's own
     `Message` alias (the type the ASGI app declares) needs none, and it follows D-07's
     rule that an `Any` inside a library's alias is not explicit in our code.

2. **`ParamSpec` needs `functools.partial`, not the bare `*args` forward RESEARCH.md
   showed.** PEP 612 requires `*args: P.args` and `**kwargs: P.kwargs` together. mypy
   rejects `*args: P.args` alone with `valid-type`. RESEARCH.md's sample then forwarded
   only `*args` to `run_in_executor`, which silently drops any keyword argument the
   signature just accepted. Wrapping the call in `functools.partial(func, *args,
   **kwargs)` forwards both. Planning verified this three ways: it type-checks, it
   catches a wrong argument type, and a partial of a module-level function pickles
   across a `spawn` `ProcessPoolExecutor` (`tests/test_pool.py` passed in the dry run).

3. **`_BlobCache` is keyed on `Hashable`, not the literal
   `tuple[GearParams, str, str, str]`.** The literal tuple breaks
   `test_the_export_cache_refuses_a_blob_bigger_than_its_budget`, which uses `str` keys
   (four `arg-type` errors in the dry run). An LRU bounded by bytes needs a hashable key
   and nothing more. The single real key shape is still documented in the comment above
   `_EXPORTS`.

4. **`GearParams.model_validate(kw)` replaces `GearParams(**kw)` in the tests now, even
   though it is not strictly needed yet.** With the rule off, `GearParams(**kw)` against
   `kw: dict[str, object]` type-checks: RESEARCH.md was right that the plugin's default
   `__init__` takes `**data: Any`. Plan 04-03 turns on typed initialisers
   (`init_typed = true`), and the `**` unpack then fails (dry run: three `arg-type`
   errors per call site). D-08 named `model_validate` as the fix for exactly that case,
   so it goes in here, where the test file is already being edited.

5. **`status` is `Literal["ok"]`.** The endpoint only ever answers "ok"; a process that
   is not alive does not answer at all. `Literal` puts `enum: ["ok"]` into the OpenAPI
   document for the healthcheck's reader. Adding a second state later would be a
   contract change either way.
</flagged_assumptions>
