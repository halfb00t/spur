<objective>
Turn the rule on, record the decision, and retire the debt, all in the order CLAUDE.md
requires.

After Plan 04-02, only one thing still stops `disallow_any_explicit` passing: the
pydantic mypy plugin, at its default settings, writes an explicit `Any` into the
initialiser it generates for every model, and reports it on the model's `class` line.
RESEARCH.md found no structural fix and recommended one suppression comment per model
class. Planning found one. The plugin's two settings `init_typed` and
`init_forbid_extra`, together (either alone is not enough), make the generated
initialiser fully typed. That takes the six errors to zero with no suppressions, and
changes nothing at runtime. This is a choice the human has not seen yet, so Task 1 asks
before anything is written to the append-only log.

Purpose: L14 promised a ratchet, not an exemption. This plan retires it the way the
debt file asked — "turn `disallow_any_explicit` on and delete this file" — and writes
down why, so no later agent turns it back off.

Output: `L21` (supersedes L14); the house rule in `docs/CODING_VALUES.md`; the rule on
in `pyproject.toml`, with the plugin settings and an honest comment; the debt file
resolved, moved, and its INDEX row moved, in the same commit as the rule turning on.
</objective>

   based on evidence gathered during planning.** RESEARCH.md (Pitfall 1 and assumption
   A2) said that only models using `Field()` produce the class-line error, that no
   structural fix exists, and that `init_typed = true` does not help. Planning re-tested
   this against the installed plugin source (`pydantic/mypy.py`, where
   `add_initializer` types each field argument as an explicit `Any` unless
   `init_typed`, and appends `**kwargs: Any` unless `init_forbid_extra` or
   `extra="forbid"`). Findings:
   - **Every** model with fields produces the error, with or without `Field()`.
   - `init_typed` alone does not fix it; `init_forbid_extra` alone does not fix it;
