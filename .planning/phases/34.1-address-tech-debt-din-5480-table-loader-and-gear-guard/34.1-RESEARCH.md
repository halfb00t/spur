## Summary

The five plans are sound on the Python/git/pytest mechanics they rest on: every claim I re-ran on this host held (subprocess timeout kills only the direct child and does not block on a pipe-holding grandchild; `cat-file -t` and `^{commit}` separate lightweight, annotated and nested tags; the bounded `Path.open` read reads 100 % branch-covered on Python 3.12.15 / coverage 7.16.2; pytest node ids with spaces and commas work when double-quoted; the `ext::` scratch origin reproduces both the hang and the `GIT_TERMINAL_PROMPT` value). The pinned sha is correct and the local tag object equals the remote's.

Four things should change the plans. (F1) The git bound `GIT_TIMEOUT_S = 10` fails the plan's own stop-and-ask precondition: the fetch the plan wants to bound reads 3.2 to 5.6 s on this host (six readings), and the "fits inside L36's 30 s" argument is stricter than it needs to be because a hung fetch aborts `make` before `test.fast` runs. (F2) The red procedure's `git checkout -- <file>` restores from the index, so on every task that writes source before its red it would discard the unstaged implementation; stage the green source first. (F3) The recommended option-b of the 34.1-01 checkpoint (all-or-none over `sizes` as well) would make `make tables.check` refuse every single-part read, which is the tool's documented use; option-a (D-05 as locked) does not. (F4) With k = 60 the cap is at most 600 for any column that has a row, so `UM_LIMIT` is only the belt for unselected columns; harmless, but the executor must not "fix" the overlap.

**Primary recommendation:** execute the plans as written, with GIT_TIMEOUT_S re-decided at 20 s (human confirms, F1), `git add` before every red (F2), and the human's edge ruling taken with F3 in front of them.

### Pattern 1: Bounded child process that cannot prompt (stdlib only)

```python
# Source: https://docs.python.org/3.12/library/subprocess.html (timeout), re-run on this host
def _git(root: Path, *args: str) -> subprocess.CompletedProcess[bytes]:
    try:
        return subprocess.run(
            ["git", "--no-optional-locks", *args], cwd=root, capture_output=True, check=False,
            stdin=subprocess.DEVNULL, timeout=GIT_TIMEOUT_S,       # read at call time: a test lowers it
            env={**os.environ, "GIT_TERMINAL_PROMPT": "0"},
        )
    except subprocess.TimeoutExpired:
        raise SystemExit(f"gear.unchanged: git {' '.join(args)} timed out after {GIT_TIMEOUT_S} s") from None
```
Reproduced: with origin `ext::sleep 10` and `timeout=1`, `TimeoutExpired` arrives at 1.00 s `[VERIFIED: scratch run, git 2.56.0]`; the test shape (pytest `-W error`, `monkeypatch`, `SystemExit` message) passes in 1.04 s `[VERIFIED: scratch run]`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Child timeout | own thread/timer + kill | `subprocess.run(timeout=)` | kills and waits the direct child, re-raises `TimeoutExpired` (docs) |
| Annotated-tag test | parse `.git/refs` or `packed-refs` | `git cat-file -t` + `rev-parse ^{commit}` | handles packed refs, nested tags |
| Bounded read | `stat` only, or read-all then check | `f.read(CAP + 1)` | the only form that bounds memory after a post-stat growth |
| Hanging remote for a test | a socket server or FIFO | git's `ext::` transport (`protocol.ext.allow always` in the scratch repo) | no network, deterministic `sleep`, reproduced here |
| Coverage proof of a refusal | assert on call counts | one broken-file case per line, seen red | CODING_VALUES: no asserting private calls |

## Common Pitfalls

### Pitfall 1: The red procedure reverts the implementation
**What goes wrong:** the task writes the rule/guard and its test, then breaks the source for the red and runs `git checkout -- <file>`; that restores from the index, which still holds the old version, so the new code is gone.
**Why:** `git checkout -- <path>` copies the index entry `[VERIFIED: scratch repo: without staging the file reads "old" after the checkout; after `git add` it reads "new" and `git diff --exit-code -- f` is clean]`.
**How to avoid:** `git add <source file>` while green, then break, run, `git checkout -- <file>`, `git diff --exit-code -- <file>`. Applies to 34.1-02 Tasks 1-3 (`scripts/gear_unchanged.py`), 34.1-03 Task 2 (`din5480_tables.py`), 34.1-04 Tasks 1-2. Plan 34.1-01 was unaffected (tests only).
**Warning signs:** the "re-run green" step goes red after the revert; `git diff` shows the old body.

### Pitfall 2: Unquoted pytest ids in zsh or `sh`
**What goes wrong:** `tests/x.py::test[a b]` splits at the space and zsh globs `[...]`.
**How to avoid:** double-quote every node id, as the plans do. Existing ids contain commas and spaces (`tolerance row negated, sum intact`) `[VERIFIED: pytest --collect-only]`; 33 BROKEN ids collect today. Several ids in one run: pass several quoted args.

### Pitfall 3: A patched `Path.open` hides a write
`write_bytes`/`write_text` use `Path.open` (3.12). Write the fixture first, then patch (plan 03 states this).

### Pitfall 4: Orphaned grandchildren after a timeout
`subprocess.run` kills only the direct child (`kill()` is SIGKILL to the child); the `ext::` `sleep 10` or an `ssh` lives on. On POSIX the parent does not block on a pipe the orphan still holds: `sh -c 'sleep 8 & sleep 8'` under `timeout=1` returned at 1.00 s `[VERIFIED: scratch run]`. (On Windows `run` calls `communicate()` after the kill and would block; not a platform of this project.) T-34.1-07 "accept" stands.

### Pitfall 5: Figure-check regex gaps
The plans' leak check greps D-01's figures by exact spelling. A shortened or reworded spelling of the same ratio (fewer decimals, "percent" written out) does not match. Widen the pattern to a prefix when plan 05 is executed (LOW; the check is a belt, the real control is that nobody writes the figures).
