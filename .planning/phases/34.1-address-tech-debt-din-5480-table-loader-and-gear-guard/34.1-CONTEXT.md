<decisions>
## Implementation Decisions

### A_s bound (debt `2026-11-01-an-oversized-a-s-cell-loads-and-shifts-every-limit`)
- **D-01:** Bound each `A_s` cell in `problems()` by a cap relative to the module: refuse `|A_s| > k*m`, with `m` the largest module of the column the cell sits in (the largest `module_max_mm` over the column rows that carry that column number) and **`k` = 60 um per mm of module, one global constant**. Measured on the real file by the human's request (aggregate only, no cell value recorded): the largest real ratio is 53.33, so 60 leaves about 12 % headroom. A 10x slip is caught on 93 of 153 nonzero cells (61 %); on cells with a small ratio a 10x slip still lands under the cap and loads. That residual is accepted: the two-reads diff (D-08 of Phase 34) stays the primary guard and a per-column cap is not taken. The commit comment carries the reasoning, never a table value.
- **D-02:** No per-letter sign rule. Letter sign conventions (f below zero, h zero, k above) are ASSUMPTION: not checked against the copy, and a sign rule would encode a claim about the standard. A sign slip stays covered by the two-reads diff (D-08 of Phase 34).
- **D-03:** The bound lives in `problems()`. No startup check from a module above both loader and `shaft_calc`: the derived order `s_min <= s_max <= s_vmax` does not catch this slip, because `A_s` moves all three together (found at this discussion; the debt item's second idea is therefore dropped, and its text is corrected in the resolving commit).
- **D-04:** The existing `UM_LIMIT` (1000 um) check on `A_s` stays as the outer belt.

### Table 7 partly present (debt `2026-11-01-table-7-partly-present-loads-and-prints-a-false-sentence`)
- **D-05:** In `problems()`, refuse a file whose four Table 7 lists (`deviations`, `classes`, `tolerances`, `columns`) are neither all empty nor all non-empty. `test_a_document_of_empty_row_tuples_loads` keeps passing. Fix as the debt item states; no discussion needed.

### Gear guard (debts `...has-no-timeout-on-git-or-probe`, `...accepts-a-lightweight-or-moved-v0-6-tag`)
- **D-06:** The `v0.6` tag must be annotated (`git cat-file -t v0.6` prints `tag`) AND peel to `792b45c` (the sha ROADMAP Phase 30 and `30-VERIFICATION.md` name). The sha is one constant in `scripts/gear_unchanged.py`; a deliberate re-baseline edits that constant. No ancestor check.
- **D-07:** Every `subprocess.run` in the script gets a `timeout=`; git runs with `GIT_TERMINAL_PROMPT=0` and `stdin=subprocess.DEVNULL`; `TimeoutExpired` becomes a `SystemExit` naming the command. Timeout values are the planner's call; they must fit inside the 30 s cap of gsd's SDK commit (L36) for the fetch, and the probe gets its own, longer bound measured on this host and recorded.
- **D-08:** Scratch-repo tests: a lightweight tag at HEAD fails; a moved annotated tag fails; an unreachable origin fails within the bound. Each seen red once, red recorded.

### Scope edge
- **D-09:** Take the dead `odd_confirmed` branch (`shaft_calc.py` ~394/405, debt `2026-11-01-limit-measurement-odd-confirmed-branch-is-dead`): delete it, do not test it. The other `shaft_calc.py` return (the "does not touch the flanks" `LimitReading`) is reachable and gets a test.
- **D-10:** Also take `load_file`'s size-cap order (nice debt `2026-11-01-load-file-reads-the-whole-file-before-its-size-cap`): read with `path.open("rb")` and `f.read(MAX_FILE_BYTES + 1)`, then one cap check on `len(raw)`; the `stat` pre-check stays for the wrong-path case. The oversize-file test (D-11) must distinguish the two checks. Same function as the `OSError` and oversize refusals D-11 tests, so one edit, one commit.
- **D-10a:** Not taken, no new debt filed: `SCHEMA_VERSION` unused and every other nice or must item outside the five audit items plus D-09 and D-10.

### Proof (the loader's unreached lines)
- **D-11:** One broken-file case per uncovered `din5480_tables.py` line (the module-set check, positive `m1_mm`, the two column-count checks, module bounds, `d_b_over_mm` below `d_b_upto_mm`, the two `OSError` paths, the file-size cap) added to the parametrised `test_a_broken_row_refuses_to_load` (or an `OSError`/oversize case for the I/O lines). Each case is seen red with its line removed; the reds go in `bench/RESULTS.md` as in earlier phases.
- **D-12:** The coverage floor does not move (96.0 % total). No per-file floor, no new Lxx for coverage. The phase reads `din5480_tables.py` and `shaft_calc.py` back at 100 % in its own gate run and records the numbers.
