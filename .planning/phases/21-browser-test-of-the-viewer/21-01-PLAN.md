## Planner decisions (phase-wide, recorded for the checker)

These settle what CONTEXT left to the planner and RESEARCH's open questions. Later plans cite them by id.

- **PD-01 -- the fixed order against the commit hook (RESEARCH Open Question 1, PATTERNS "Order tension").** The commit
  hook runs `make verify.fast`, which collects every `tests/test_*.py` it finds -- committed or merely present in the
  working tree (pre-commit stashes unstaged edits, not untracked files). So a file called `tests/test_browser.py` cannot
  exist anywhere before its `--ignore` is committed. Rather than land the exclusions first (the research's
  recommendation), the scenarios are developed in **`tests/browser_scenarios.py`**, a module pytest collects only when it
  is named on the command line (it matches neither `test_*.py` nor `*_test.py`, and pytest collects an explicitly named
  file regardless of `python_files`). Neither `make verify` nor `make verify.fast` runs it, while ruff and mypy check it
  from its first commit. **21-06's single admission commit** renames it to `tests/test_browser.py` together with both
  `--ignore`s, the `HEAVY_TEST_FILES` pin, the `-o` fix, the stamp as a prerequisite of `test` and `ci.yml`. That honours
  the roadmap order (spike, then scenarios, then admission in one commit, then the cost and the `Lxx`) and SC4's letter
  ("excluded ... in the same commit that adds the file"), and keeps every intermediate commit green under both
  `make verify.fast` and `make verify` with no temporary edit to a gate recipe or pin. Rejected: exclusions first and the
  file committed early (`make verify`'s `test` would collect it before the stamp is its prerequisite, so the gate is red
  on any checkout without the shell, or the file is admitted in fact before the admission commit); keeping the file
  uncommitted (the hook collects untracked files too).
- **PD-02 -- the Linux runner in the spike.** CI runs only what `make verify` collects on a pull request, and the phase
  branch admits nothing before 21-06. 21-02 therefore builds a throwaway branch `spike/21-linux-runner` carrying the
  admission wiring plus `PYTEST_ARGS: -rP` so the tracer's per-step readings print in the runner's log; the human pushes
  it as a draft PR titled do-not-merge; it is never merged and nothing from it reaches the phase except recorded readings
  and ported fixes. SC5's own real run is 21-08's, on the phase's head.
- **PD-03 -- the canvas bar (pre-registered; D-05).** `PNG_RATIO_BAR` = the lower of the hosts' drawn/blank PNG byte
  ratios divided by 2, rounded down to one decimal place. 21-01 applies it to the macOS reading, 21-02 to the lower of the
  macOS and ubuntu-latest readings. If the result is below 2.0 the reading cannot tell a drawn canvas from a blank one
  with margin, and the plan stops for the human instead of asserting it. (A blank canvas reads a ratio near 1.0; the
  research reading was 9.93.)
- **PD-04 -- waits (Pattern 3).** DOM waits keep Playwright's default 5000 ms, so a DOM regression fails in 5 s.
  Build-bound waits pass `timeout=BUILD_WAIT_MS` = 45 000 ms (`SPUR_BUILD_TIMEOUT` 30 s plus margin); if the slowest
  build-bound step seen on either host is over 15 s, `BUILD_WAIT_MS` becomes three times that, rounded up to the next
  5 s, recorded with the reading. No `wait_for_timeout` and no `time.sleep` anywhere as a wait signal.
- **PD-05 -- the 422 scenario (Open Question 2).** `#bore_flat=3` is the required case (the only single-field
  `ctx.fields` 422, `params.py:184-187`); `#teeth=2` is a second assertion for the `loc[1]` path.
- **PD-06 -- the warning links.** `#module=1&pressure_angle=14.5` (its API `warnings` list is asserted to hold at least
  two entries, so equality and not containment is what is proved) and `#bore_hex=6` (the hex-link baseline Phases 23-24
  inherit). The STL route is fulfilled with the first build's bytes, so the warnings survive (Pitfall P7 is about an
  aborted STL) and the scenario test still draws exactly one real part (CONTEXT specifics).
- **PD-07 -- `data-triangles` after a failed build (discretion).** It keeps the previous count, at no code cost (a failed
  build never reaches `showModel`), matching the status text "Showing the last valid gear"; the test asserts the retained
  count after the truncated STL (21-01) and after both 422s (21-03).
- **PD-08 -- the golden pin (Open Question 5, D-09).** The `api/info` query only (the STL query is `q` plus
  `quality=preview` by construction, `app.js:206-207`). `tests/regression/golden_requests.json` holds
  `{"records": {name: query}, "regenerate": "<one sentence>"}` written with `sort_keys=True`, indent 2 and a trailing
  newline, and no volatile provenance (no date, no sha), so a regen on unchanged code is an empty diff. Target:
  `make golden.regen`.
- **PD-09 -- no convenience target (Open Question 6).** Before admission the quick run is
  `make .venv/.browser && make test PYTEST_ARGS="tests/browser_scenarios.py -n0 --no-cov -q"`; after it,
  `make test PYTEST_ARGS="tests/test_browser.py -n0 --no-cov -q"`.
- **PD-10 -- the `.gitignore` boundary.** The shell lives under `.venv/`, already ignored. 21-01 Task 3 records what a
  browser run leaves (`git status --porcelain --ignored`); 21-06 documents `.venv/`'s new content in a comment beside the
  `.venv/` entry and adds an entry only for a path that reading found outside `.venv/`. The test writes no file.
- **PD-11 -- the `#root_shape=bogus` debt's severity (Open Question 3).** `must`, trigger "Phase 23 or 24 touches

- **PD-13 -- retiring an idea (the first ever).** Mirror the debt ledger: `Status: retired`, `Retired in: <commit
