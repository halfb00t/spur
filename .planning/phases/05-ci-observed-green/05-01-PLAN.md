<flagged_assumptions>
1. **Python, not bash, for the hook -- a departure from RESEARCH.md's recommendation.**
   RESEARCH recommended a bash/grep script. Plan 05-02's `make pr.land` must refuse a
   merge whose squash subject or body carries a token (after D-03, that text *is* the
   commit message `main` receives, and no commit-msg hook ever sees it). One pattern in
   one importable module is the only way the two checks cannot drift apart. A Python
   module also sits under mypy `--strict` and is tested by direct import, the way
   `bench` is. Record the choice in `05-01-SUMMARY.md`.

2. **The `verify` hook must be pinned to the `pre-commit` stage.** Not in RESEARCH or
   CONTEXT; found during planning by reading the installed pre-commit
   (`pre_commit/repository.py`: a hook without `stages` gets the top-level
   `default_stages`, which defaults to every stage) and proven in a scratch repository:
   with `default_install_hook_types: [pre-commit, commit-msg]`, an unpinned hook ran
   twice per commit; pinned, once. Unpinned, every commit here would run the ~42 s
   `make verify` twice.

3. **The scissors cut.** Also found during planning, in the same scratch repository:
   `git commit -v` (or `commit.verbose=true`) hands the commit-msg hook the whole
   editor buffer, including the staged diff below git's
   `------------------------ >8 ------------------------` line. A whole-file scan refused
   a commit whose only token was in the diff of an added file -- and this phase's own
   docs and tests name tokens. Git discards everything below that line, so the hook
   checks only the text above it. Comment lines (starting with `#`) are **not** skipped:
   with `-m`, git's cleanup mode keeps them, so a token in one would reach the commit.

4. **`.venv/bin/python` as the hook's interpreter.** The `verify` hook already requires
   the venv `make venv` builds, and pre-commit runs the `pre-commit` stage (which builds
   it if missing) before the `commit-msg` stage. A missing venv makes the hook fail,
   which refuses the commit: it fails closed.

5. **The sha recorded in the debt file is Task 1's commit, not Task 2's.** A file cannot
   carry its own commit's sha. The convention (`21b8fe4` in Phase 3, `013900d` in Phase
   4) names the commit that landed the core fix and resolves the file in the commit that
   completes it. Here that is the hook (Task 1); Task 2 applies and records D-03 and
   moves the file. ROADMAP SC-4 says "in the same commit as the hook + setting": on
   `main` the phase is one squash commit, so both land together there; on the branch,
   the debt file stays `active` for exactly one commit, while the fix is genuinely
   incomplete.

6. **`make test-image` cannot import `scripts`.** It mounts only `src/` and `tests/`. The
   same is already true of `bench` (imported by `tests/test_bench.py`). `test-image` is
   not part of `make verify` or `make check`; this phase does not change it.

7. **Live repository facts differ from CONTEXT.md** (read with `gh api` during
   planning, 2026-09-25): the repository is **public** (CONTEXT recorded private on a
   free plan), `delete_branch_on_merge` is `true`, and an active ruleset named
   `default` exists whose branch condition includes no branch (`rules/branches/main`
   returns `[]`). The human has since decided **D-12** (supersedes D-06): a ruleset on
   `main` requiring green CI, applied in Plan 05-03. None of this changes this plan, except
   that the debt file's Resolution section records the corrected premise (Task 2).
</flagged_assumptions>
