<objective>
Close the two items that make `make pr.land`'s run verdict weaker than L22 promises (D-04,
D-05):

- `head_refusals` judges a completed run only by the jobs listed in the *local*
  `required-jobs.txt`, never by the run's own `conclusion` (already parsed by `parse_runs`,
  never read). A PR that adds a job that fails, landed from a checkout whose list predates
  it, sees three green listed jobs and merges (Codex review of PR #4, finding 1).
- The drift test holds `required-jobs.txt` equal to `ci.yml`'s job *ids*; GitHub reports a
  job by `jobs.<id>.name` when set, so a rename slips past the test and every merge then
  stalls on a check no job reports.

**D-04**: refuse when `run.conclusion != "success"`, naming the conclusion and the run URL,
*and* keep the per-job loop (it names a missing job). The stale-checkout half is closed by
rule, not by a fetch: §8 says `make pr.land` runs from an up-to-date `main`.
**D-05**: the drift test resolves the effective name, scoped to each job's block.

Live evidence gathered at planning (read-only `gh`, 2026-09-25): run 36116930241 (head
`73535a2`, a Phase 5 PR head) is `completed` / `failure` with `test (3.12)` failed and
`vendor-bundle`, `image` green; `compare/main...73535a2` reads `{"ahead_by":37,"behind_by":1}`.
Today `check_head` on that head returns two refusals (behind, `test (3.12)`); after D-04 it
returns three, one naming the run's conclusion and URL -- Task 1's live probe.

**Task 1, the tracer**: the refusal wired through `head_refusals`/`check_head`, proven offline
and live against the real run. **Task 2**: the drift test reads names. **Task 3**: §8 and both
debt files, in the commit that completes both fixes.

Purpose: "green" means the run's own verdict *and* every named job (CONTEXT.md specifics).
Output: `head_refusals` + tests; the drift test; §8; two resolved debt files.
</objective>
